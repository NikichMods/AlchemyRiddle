# Product coherence audit — 2026-10-06

Status: **broad product/design audit complete; selected puzzle architectures remain accepted; production remains BLOCKED**.

## Scope

This audit checks the current AlchemyRiddle design against:
- the durable product invariant and acceptance envelope;
- current selected two-slot and three-slot cores;
- progression/curriculum decisions;
- real-corpus quantitative evidence;
- blind paper-prototype evidence;
- prior external design validation;
- newly accepted intellectual-interest / anti-pseudocomplexity rules;
- current repository source-of-truth consistency.

It is not a production implementation audit and does not establish runtime hook ownership.

## Current product architecture

Accepted core:
- entry: visible need for unknown product -> journal lead -> player-selected investigation;
- two-slot: fixed reagent properties + logical constraints;
- three-slot: adaptive knowledge-aware properties + adjacent STABLE/INCOMPATIBLE relations + logical constraints;
- property vocabulary: accepted Dark + Organ enriched model;
- theoretical formula deduction is separate from practical reagent/source mastery;
- successful deduction unlocks formula knowledge immediately;
- one unsolved deduction active at a time, persistent across interruption;
- free target choice preserved;
- independent arity ladders with shared logical concept transfer;
- compact onboarding -> rich/hard -> early MAX -> mature plateau -> selected boss peaks;
- formula submission must not become a free brute-force oracle;
- intellectual interest / inference quality is separate from nominal difficulty.

## Coherence audit

### Product invariant — PASS

The selected systems still support the intended player conclusion:
"I worked out this recipe."

No accepted mechanic requires prior formula knowledge, wiki lookup or blind full
enumeration. Targeting begins from a concrete product need rather than from
random workstation mixing.

### Fair deduction / information honesty — PASS

- reagent properties are stable rather than puzzle-specific;
- accumulated relation knowledge remains valid and is not hidden to manufacture
  difficulty;
- theoretical identities may be exposed, but formula answers are not directly
  disclosed;
- experiments/actions are expected to produce interpretable information rather
  than ritual clicks.

### Cognitive-load / onboarding discipline — PASS

- one genuinely new concept at a time under reduced surrounding load;
- shared two-slot concepts transfer into three-slot play;
- onboarding is deliberately short;
- difficulty is multidimensional rather than board-size-only;
- journal/compendium acts as external memory for interruption-heavy Graveyard
  Keeper play.

### Difficulty versus interest — PASS in principle, OPEN in generation

The design now explicitly rejects the equation "harder = better".

Accepted:
- flat serial filtering can be hard but uninteresting;
- mature puzzles should prefer cross-clue inference and derived condition
  activation;
- every band, including tutorial, should contain worthwhile reasoning when
  possible.

Open:
- no accepted positive structural metric yet distinguishes a generated
  intellectually-interesting clue graph from a merely valid/non-redundant one;
- the first matched HARD/MAX examples exposed this gap and were correctly
  rejected as positive exemplars.

This is now the highest-leverage product/generator uncertainty.

### Brute-force resistance — PASS as invariant, OPEN in economy

The product correctly treats formula submission as an information oracle and
requires anti-bruteforce containment.

Still open:
- exact wrong-answer feedback;
- exact Science price / whether cost is needed when deduction is already unique;
- quantitative proof that the chosen interaction is less attractive than
  reasoning for a resource-rich player.

### Progression / corpus fit — PASS

Accepted corpus evidence supports:
- every mandatory two-slot target variant carrying tested compact curriculum
  beats;
- every ordinary three-slot variant carrying the first relation tutorial;
- large mature puzzle-surface reserve for both arities;
- free target choice without reserving a curriculum-compatible formula;
- realistic natural-demand exposure shorter than the full completionist corpus,
  which supports early MAX rather than reserving mature play for the tail.

### Variety / repetition — PASS with ordinary tuning risk

Current property and anti-repeat policy provide large field choice reserves and
good control over repeated reagent identity.

Residual repetition of exact property signatures exists but no longer justifies
taxonomy expansion after Dark + Organ. Reopen only if blind sequence play exposes
a real stale-feeling problem.

### Three-slot experimental layer — PASS

Blind prototypes support:
- purposeful adjacent relation tests;
- direct/mirrored/mixed relation orientation;
- bridge and residual/off-bridge reasoning;
- clue-led, experiment-led and mixed trajectories.

Do not force a minimum number of experiments merely for activity.

### Two-slot agency — ACCEPTED level-3 shape, watch item

The selected two-slot core is primarily deductive narrowing rather than an
experiment-heavy black-box system. This is consistent with the product quality
ladder: it can satisfy the target at level 3 even if three-slot play more often
approaches level 4 experimental deduction.

Watch for static "read clues then solve" monotony in blind sequence play; solve
that through inference-quality and presentation/variety evidence before reopening
the architecture.

### Spoiler / world integration — ACCEPTED tradeoff

Real reagent names/properties may appear before practical mastery. This is an
explicit accepted abstraction cost, bounded by:
- target-first exposure;
- soft penalty for unnecessary unknown decoys;
- no automatic source research for decoys;
- practical source/preparation knowledge remains separate.

No contradiction with the core anti-formula-spoiler invariant was found.

## Highest-leverage next step

Do **not** start production and do **not** run another broad corpus screen yet.

Next:
1. define a small positive vocabulary of **interesting inference structures**
   (not clue families) using revised matched examples;
2. blind-test a minimal set across easy/rich and mature/boss two-slot cases, then
   one representative three-slot case;
3. from those results, write a generator acceptance contract for inference
   quality;
4. only then test whether the real corpus can supply those structures broadly.

The exact research question is:
> Can AlchemyRiddle generate short, target-specific puzzles whose uniqueness
> comes from meaningful cross-clue inference rather than flat filtering, across
> the practical progression range?

This is a concrete new structural uncertainty and therefore justifies a later
bounded corpus screen if the positive player-facing patterns are first defined.
